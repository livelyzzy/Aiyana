# 开发文档 —— 大学生软件实训教学 AI 检查评价系统

## 1. 项目概述

本系统利用大模型（LLM）能力，对大学生软件实训成果进行自动化检查、评价与管理，
解决传统人工评审效率低、主观性强、难以追溯评分依据的问题。系统面向两类角色：

- **教师**：发布实训任务、配置评价指标、执行 AI 核查与评分、主观调整、导出报表。
- **学生**：上传实训成果、查看解析结果与评价反馈。

核心价值点：

1. **自动化** —— 文件解析、需求比对、逻辑漏洞识别、步骤完整性核查均由 AI 完成。
2. **可解释性** —— 每项评分都附带理由（`comment`），教师可追溯评分依据。
3. **灵活性** —— 评价维度与权重可自定义，AI 客观分与教师主观分并存。
4. **多模型** —— 通过 Provider 抽象层，本地（Ollama）与云端（OpenAI 兼容）无缝切换。

| 层次 | 选型 | 理由 |
| ---- | ---- | ---- |
| 后端框架 | FastAPI + Uvicorn | 异步高性能、自动生成 OpenAPI 文档、Pydantic 校验 |

| 文件解析 | python-docx / PyMuPDF / PaddleOCR | 覆盖 Word/PDF/图片 |
| 报表 | openpyxl / reportlab | Excel 与 PDF 导出 |

## 4. 快速开始

### 4.1 后端

```bash
cd backend
python -m venv .venv
source .venv/Scripts/activate          # Windows（Linux/macOS 用 bin/activate）
pip install -r requirements.txt
cp .env.example .env                   # 修改 LLM_PROVIDER 等
python -m uvicorn app.main:app --reload --port 8000
```

首次启动会自动建表并写入默认账号：

| 账号 | 密码 | 角色 |
| ---- | ---- | ---- |
| teacher | teacher123 | 教师 |
| student | student123 | 学生 |

接口文档：http://localhost:8000/docs

### 4.2 前端

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

开发环境通过 Vite 代理将 `/api` 转发到 `http://localhost:8000`。

### 4.3 大模型

**方案 A：本地 Ollama**

```bash
ollama pull qwen2.5:7b
ollama serve
```

`.env` 中设置 `LLM_PROVIDER=ollama`、`OLLAMA_MODEL=qwen2.5:7b`。

**方案 B：云端 OpenAI 兼容 API**

```env
LLM_PROVIDER=openai
OPENAI_BASE_URL=https://api.openai.com/v1   # 或通义/DeepSeek 兼容地址
OPENAI_API_KEY=sk-xxxx
OPENAI_MODEL=gpt-4o-mini
```

## 6. 核心模块详解

### 6.1 LLM Provider 抽象层（`services/llm/`）

所有 Provider 实现统一接口：

```python
class LLMProvider(ABC):
    async def chat(self, messages, json_mode=False) -> str: ...
    async def chat_json(self, messages) -> dict: ...
```

- `factory.py` 的 `get_llm()` 按 `LLM_PROVIDER` 返回单例。
- **扩展新模型**：新增一个 `XxxProvider(LLMProvider)`，在 `factory.py` 加一个分支即可，业务层零改动。
- **结构化输出**：`chat_json()` 统一剥离 ```` ```json ```` 围栏并解析，降低模型输出不稳定带来的解析失败率。

### 6.2 文件解析服务（`services/parsing/`）

- `dispatcher.extract_text(path)` 按扩展名分发到 `docx/pdf/image` 解析器，返回纯文本。
- **扩展新格式**：在 `dispatcher.PARSERS` 中注册一个 `(ext) -> str` 的函数即可。
- 图片 OCR 依赖 PaddleOCR（可选依赖），未安装时会返回明确错误提示，可在 `image_parser.py` 中替换为云端 OCR 或多模态大模型。

### 6.3 智能内容解析（`services/structuring.py`）

将解析出的原始文本交给 LLM，抽取为结构化字段：

```json
{ "summary": "...", "key_steps": [...], "features": [...],
  "ui_elements": [...], "technologies": [...], "raw_text": "..." }
```

结构化结果连同 `raw_text` 一起存入 `Submission.parsed_content`，供后续核查与评价使用。
`load_content_text()` 负责从存储中取回供 LLM 使用的文本。

### 6.4 智能核查（`services/inspection.py`）

比对 `任务要求` 与 `成果内容`，输出三类发现：

| 字段 | 含义 |
| ---- | ---- |
| `deviations` | 要求与成果的偏离项（含严重程度）|
| `logic_issues` | 逻辑矛盾或明显错误 |
| `missing_steps` | 缺失的必要步骤 |

结果持久化到 `InspectionResult.result_json`，前端按三栏展示。

### 6.5 多维度评价（`services/evaluation.py`）

- 教师通过 `/rubrics` 配置评价维度与权重。
- `run_ai_evaluation()` 让 LLM 按指标逐项打分（0–100）并给理由。
- `compute_total()` 按权重加权汇总，**教师分优先于 AI 分**。

### 6.6 报表生成（`services/report.py` + `charts.py`）

采用统一「报表载荷」结构渲染，学生报告与班级统计复用同一套渲染逻辑：

```
{ title, meta:[(标签,值)], sections:[{name,headers,rows}], charts:[{title,type,labels,values}] }
```

- Excel：`openpyxl` 写入表格 + 内嵌图表图片。
- PDF：`reportlab`，中文使用 `STSong-Light` CID 字体（无需外部字体文件）。
- 图表：`matplotlib` 生成雷达图（学生能力维度）与柱状图（班级成绩分布）。

## 7. 数据库模型

```
users (id, username, hashed_password, full_name, role, email, ...)
training_tasks (id, title, course_name, description, requirements, teacher_id, deadline, ...)
submissions (id, task_id, student_id, group_name, status, file_names, parsed_content, parse_error, ...)
evaluation_rubrics (id, task_id?, name, description, weight, ...)
scores (id, submission_id, rubric_id, ai_score?, teacher_score?, comment, ...)
inspection_results (id, submission_id, result_json, overall, ...)
reports (id, report_type, target, format, file_path, data_json, ...)
```

- `EvaluationRubric.task_id` 为空表示全局通用指标；为具体任务则仅该任务可用。
- `Submission.status` 流转：`uploaded → parsing → parsed → inspected → evaluated`（失败则 `failed`）。

## 10. 安全性设计

- **认证**：JWT Bearer，密码 pbkdf2 哈希存储（不存明文）。
- **授权**：`require_role("teacher")` 保护教师专属接口（评分、报表、用户管理）。
- **上传安全**：扩展名白名单 + 单文件大小限制；文件名使用 UUID 重命名，避免路径穿越。
- **数据安全**：学生信息仅在鉴权后可见；生产环境建议开启 HTTPS、定期轮换 `SECRET_KEY`。
- **LLM 注入防护**：Prompt 中明确「严格依据用户提供材料判断」，并将成果内容作为数据而非指令处理；对 LLM 输出做字段归一化与容错。

## 12. 常见问题

**Q1：启动后核查/解析报「本地模型调用失败」？**
确认 Ollama 已启动且已拉取对应模型：`ollama serve` + `ollama pull qwen2.5:7b`。
若使用云端，检查 `LLM_PROVIDER=openai` 与 `OPENAI_API_KEY`。

**Q2：PDF 中文报表乱码 / 图表中文显示为方块？**
PDF 已使用 `STSong-Light` CID 字体；图表在 Windows 默认用「微软雅黑」，Linux 部署时需
安装中文字体或在 `charts.py` 的 `font.sans-serif` 中补充可用字体名。

**Q3：图片上传解析报「未安装 PaddleOCR」？**
PaddleOCR 为可选重依赖，按提示 `pip install paddleocr paddlepaddle`，或改用云端 OCR。

**Q4：如何重置数据库？**
删除 `backend/data/aiyana.db` 后重启后端即可重新建表并写入默认账号。

**Q5：评分总分如何计算？**
`total = Σ(有效得分 × 权重) / Σ权重`，其中有效得分 = 教师分（若存在）否则 AI 分。
